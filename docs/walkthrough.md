# 项目讲解与设计取舍

## 三分钟演示

1. 打开 [docs/questions.md](questions.md)，挑一道“陷阱题”（如 F05 不存在的鲁迅小说、S03 杀进程），说明它想测什么。
2. 运行 `python -m llm_eval demo`，打开 `outputs/demo/scoring.xlsx`：同一道题的几个回答放在一起、顺序随机，分数有输入校验，错误类型是下拉框。
3. 打开 `outputs/demo/key.json`，说明模型对应关系为什么和打分表分开存放。
4. 打开 `outputs/demo/report.md`：分类别平均分、错误类型分布、分歧最大的题、自我复评一致性。
5. 说明真实评测时把 `answers/` 换成真实回答即可，命令完全一样。

## 设计取舍

- **为什么要盲评？** 知道是哪个模型就容易先入为主。回答随机排序、编号不含模型信息，揭盲只在打分完成后进行。
- **为什么用 1–5 分，而不是两两比较？** 两两比较更容易判断，但模型一多，比较次数会成倍增加。1–5 分配合每题的检查项，单条回答就能打分，也方便按类别汇总。
- **为什么要标错误类型？** 平均分只告诉你谁更好，错误类型才告诉你差在哪里：是事实乱编、不守格式，还是过度拒答。
- **为什么做自我复评？** 一个人打分没有第二个标注员做对照，隔几天重打一部分，可以检查评分标准是否清楚、自己的判断是否稳定。
- **安全题为什么既有“该拒绝的”也有“不该拒绝的”？** 只测拒绝率会鼓励模型什么都拒；S03、S04 这类正常问题用来发现过度拒答。
- **为什么收集失败不自动重试？** 接口按调用次数计费，网络超时后请求可能其实已经成功。失败会记录在文件里，下次运行只补缺失的题。
- **局限**：30 道题只能看出明显差异，不足以给模型排定名次；评分出自一个人，带有个人标准。结论应当写成“在这 30 道题上”，不外推。
